# Question 19: The Concept of Grain in a Fact Table

**Topics:** Grain, Fact Table, Dimensional Modeling

## 📝 Question

> In designing a Fact table, what is meant by Grain?

## 🔢 Options

**Option 1:** The total size of the database file in bytes

**Option 2:** The number of columns with a numeric data type

**Option 3:** The number of relationships the table has with other tables

**Option 4:** The level of detail that each row of the table represents

## 💡 About this question

**Grain** specifies "exactly what each row of the Fact table means." Example: "one row = one item on an invoice" or "one row = daily sales of each store."

Declaring the grain is the **first and most important decision** in Fact design; it determines which dimensions and measures are allowed and prevents errors such as duplicated values in joins.

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> The total size of the database file in bytes

**Incorrect.** The size of the database file has nothing to do with grain.

### Option 2 — ❌ Incorrect

> The number of columns with a numeric data type

**Incorrect.** The number of numeric columns concerns table structure, not the level of detail each row represents.

### Option 3 — ❌ Incorrect

> The number of relationships the table has with other tables

**Incorrect.** The number of relationships concerns how tables connect; grain is about the meaning of each row.

### Option 4 — ✅ Correct

> The level of detail that each row of the table represents

**Correct.** Grain is the level of detail that each row of the table represents (for example, each invoice line).

## ✅ Correct answer

**Option 4**

> The level of detail that each row of the table represents

## 🎯 Why it is correct

Grain defines what a row is; that is precisely the level of detail.

## 📌 Key takeaway

Before designing a Fact, write one sentence: “each row represents ...”.
