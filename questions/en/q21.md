# Question 21: Idempotent ETL Pipelines

**Topics:** ETL, Idempotency, Re-runnability, Data Quality

## 📝 Question

> What does it mean for an ETL pipeline to be idempotent?

## 🔢 Options

**Option 1:** It should have the fastest possible execution

**Option 2:** It should run only on new data

**Option 3:** Re-running it with the same input should give the same result and create no duplicate records

**Option 4:** It should run without logs

## 💡 About this question

An **idempotent** pipeline is one where **running it multiple times with the same input yields the same result as running it once**. Why it matters: if an ETL run fails midway or we have to re-run it, it must not create duplicate records or wrong totals.

Common techniques: `MERGE/UPSERT`, deleting/replacing the same period's partition, unique natural keys and run-state tracking.

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> It should have the fastest possible execution

**Incorrect.** Execution speed has nothing to do with idempotency. A fast pipeline may duplicate data when re-run.

### Option 2 — ❌ Incorrect

> It should run only on new data

**Incorrect.** Running only on new data (incremental) is a loading pattern; being idempotent means re-running on the same input does not change the result, even if old data is processed again.

### Option 3 — ✅ Correct

> Re-running it with the same input should give the same result and create no duplicate records

**Correct.** The definition of idempotent: re-running with the same input ⇒ the same result and no duplicate records.

### Option 4 — ❌ Incorrect

> It should run without logs

**Incorrect.** Running without logs is neither a part of idempotency nor good advice; logs are needed for monitoring and debugging.

## ✅ Correct answer

**Option 3**

> Re-running it with the same input should give the same result and create no duplicate records

## 🎯 Why it is correct

Idempotent = safe re-runs: same result, no duplicates.

## 📌 Key takeaway

Write ETL so that re-running (retry/backfill) does not duplicate data.
