# Question 7: Benefit of Columnar Storage in a Data Warehouse

**Topics:** Data Warehouse, Columnar Storage, Compression, OLAP

## 📝 Question

> What is the main advantage of columnar storage in a data warehouse?

## 🔢 Options

**Option 1:** More suitable for bank transactions

**Option 2:** Reading less data and better compression for analyzing multi-column queries

**Option 3:** Eliminates the need for modeling

**Option 4:** Higher speed for single-row updates

## 💡 About this question

In **row-based** storage all columns of a row are stored together, which suits recording and updating a full record. In **columnar** storage the values of each column are stored together.

In analytics (e.g., total sales by region) usually only a few columns out of dozens are needed. Columnar storage reads only those columns, and because the values in a column are similar and of the same type, it **compresses** far better.

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> More suitable for bank transactions

**Incorrect.** Bank transactions (frequent recording and updating of whole records) are the job of OLTP systems and row-based storage, not columnar.

### Option 2 — ✅ Correct

> Reading less data and better compression for analyzing multi-column queries

**Correct.** An analytical query reads only the needed columns (less I/O), and the same-type data in columns compresses better; this is the main advantage of columnar storage for a data warehouse.

### Option 3 — ❌ Incorrect

> Eliminates the need for modeling

**Incorrect.** Columnar storage has nothing to do with eliminating modeling. Even in a columnar warehouse, modeling (Star Schema, etc.) is still needed.

### Option 4 — ❌ Incorrect

> Higher speed for single-row updates

**Incorrect.** Single-row updates are usually **slower** in columnar storage, because one record is spread across several separate columns. That is an advantage of row-based storage.

## ✅ Correct answer

**Option 2**

> Reading less data and better compression for analyzing multi-column queries

## 🎯 Why it is correct

Analytics = reading a few columns across a large number of rows. Columnar storage reads only those columns and compresses better.

## 📌 Key takeaway

Columnar → analytics (OLAP); row-based → transactions (OLTP).
