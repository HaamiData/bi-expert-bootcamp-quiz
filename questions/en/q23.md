# Question 23: One-to-Many Join and Repeated Customer Info

**Topics:** Joins, One-to-Many Relationship, Grain

## 📝 Question

> In the orders table, each customer can have several orders. When joining the customers table to the orders table, the information of one customer may appear in several rows. When is this situation normal?

## 🔢 Options

**Option 1:** Whenever the customers table has a primary key

**Option 2:** Only when the data has been imported from two files with different formats

**Option 3:** Only when a customer's name was recorded incorrectly

**Option 4:** When several orders belong to one customer and the result of the join is displayed at the order level

## 💡 About this question

The customer-to-order relationship is **one-to-many**. When we join the customers table (grain: one row per customer) to the orders table (grain: one row per order), the output is at the **order** level; so a customer with 5 orders is repeated 5 times. This is **normal behavior** of a one-to-many join, not an error.

An unexpected repetition (e.g., duplicate rows in the customers table or a non-unique key) is when it becomes a problem.

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> Whenever the customers table has a primary key

**Incorrect.** Having a primary key is a property of the customers table and is not itself the cause of repetition; the repetition comes from the one-to-many relationship with orders. (In fact a unique primary key guarantees there are no duplicate customers in the customers table.)

### Option 2 — ❌ Incorrect

> Only when the data has been imported from two files with different formats

**Incorrect.** Different file formats have nothing to do with the natural repetition; in a one-to-many join the repetition happens even with one source and one format.

### Option 3 — ❌ Incorrect

> Only when a customer's name was recorded incorrectly

**Incorrect.** A mistyped customer name is not the cause of join-induced repetition. The natural repetition comes from several orders per customer, not from a recording error.

### Option 4 — ✅ Correct

> When several orders belong to one customer and the result of the join is displayed at the order level

**Correct.** When one customer has several orders and the join result is shown at the order level, the customer's information repeats across several rows, and this is natural behavior.

## ✅ Correct answer

**Option 4**

> When several orders belong to one customer and the result of the join is displayed at the order level

## 🎯 Why it is correct

One-to-many relationship + order-level output ⇒ repeated customer info is natural.

## 📌 Key takeaway

In a one-to-many join the “one” side repeats; when aggregating measures from the “one” side beware of double counting (see Question 2).
