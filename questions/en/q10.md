# Question 10: Role of the Fact Table in a Star Schema

**Topics:** Dimensional Modeling, Fact, Dimension, Dimension Keys

## 📝 Question

> In dimensional modeling with the Star Schema pattern, what is the main role of the Fact table?

## 🔢 Options

**Option 1:** Storing business events or observations, dimension keys and analyzable values

**Option 2:** Storing merely the names and textual descriptions of customers and products

**Option 3:** Defining user security roles in Power BI

**Option 4:** Storing only metadata such as table descriptions and column names

## 💡 About this question

A Star Schema has two kinds of tables:

- **Fact:** stores business events or observations (sales, transactions, visits...). It contains **dimension keys** (foreign keys to Dimensions) and numeric, analyzable **measures**.
- **Dimension:** descriptive information (customer name, product category, date...).

## 🔍 Detailed review of every option

### Option 1 — ✅ Correct

> Storing business events or observations, dimension keys and analyzable values

**Correct.** The Fact table stores business events with dimension keys and numeric analyzable values (such as amounts and quantities) and sits at the center of the star.

### Option 2 — ❌ Incorrect

> Storing merely the names and textual descriptions of customers and products

**Incorrect.** Storing names and textual descriptions of customers and products is the job of **Dimension** tables, not Fact.

### Option 3 — ❌ Incorrect

> Defining user security roles in Power BI

**Incorrect.** Security roles (Row-Level Security, etc.) are defined at the semantic-model/Power BI level and have nothing to do with the Fact table's job.

### Option 4 — ❌ Incorrect

> Storing only metadata such as table descriptions and column names

**Incorrect.** Metadata such as table descriptions and column names is not the Fact table's analytical data; Fact stores real values and events.

## ✅ Correct answer

**Option 1**

> Storing business events or observations, dimension keys and analyzable values

## 🎯 Why it is correct

Fact = events + dimension keys + measures. The other options describe the jobs of Dimensions, security or metadata.

## 📌 Key takeaway

Fact: “what happened and how much”; Dimension: “who, what, where, when”.
