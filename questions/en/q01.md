# Question 1: Measures and Dimensions

**Topics:** BI Fundamentals, Measure, Dimension, Data Modeling

## 📝 Question

> Which option correctly shows a Measure and a Dimension?

## 🔢 Options

**Option 1:** Both are Measures

**Option 2:** Measure: sales amount — Dimension: sales region

**Option 3:** Measure: product code — Dimension: gross profit

**Option 4:** Measure: customer name — Dimension: number of invoices

## 💡 About this question

This question tests the most basic distinction in analytical modeling:

- **Measure:** a numeric value that can be **aggregated** (sum, average, count, etc.), such as sales amount, profit, number of invoices.
- **Dimension:** a **descriptive** attribute used to slice, group or filter data, such as region, product, customer, date.

Put simply: a Measure answers "how much?" and a Dimension answers "by what?".

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> Both are Measures

**Incorrect.** This option says both are Measures, so it introduces no Dimension at all. In data analysis both roles are needed, and the question asks for one Measure and one Dimension.

### Option 2 — ✅ Correct

> Measure: sales amount — Dimension: sales region

**Correct.** "Sales amount" is a numeric, aggregatable value (Measure), and "sales region" is a descriptive attribute used to slice sales (Dimension).

### Option 3 — ❌ Incorrect

> Measure: product code — Dimension: gross profit

**Incorrect.** The roles are reversed. "Product code" is an identifier/descriptive attribute (a Dimension or dimension key) and summing codes is meaningless; "gross profit" is an aggregatable number (Measure).

### Option 4 — ❌ Incorrect

> Measure: customer name — Dimension: number of invoices

**Incorrect.** This is reversed too. "Customer name" is a descriptive attribute (Dimension) and "number of invoices" is an aggregatable number (Measure).

## ✅ Correct answer

**Option 2**

> Measure: sales amount — Dimension: sales region

## 🎯 Why it is correct

A Measure must be numeric and aggregatable, and a Dimension must be descriptive and usable for slicing and grouping. Only option 2 pairs them correctly.

## 📌 Key takeaway

Measure = aggregatable number; Dimension = descriptive attribute for slicing and grouping.
