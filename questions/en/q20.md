# Question 20: Snowflake Schema vs Star Schema

**Topics:** Snowflake, Star Schema, Normalization, Joins

## 📝 Question

> What is the difference between Snowflake Schema and Star Schema?

## 🔢 Options

**Option 1:** In Snowflake, Dimension tables are normalized and the number of Joins increases

**Option 2:** Schema is always slower

**Option 3:** All items are correct

**Option 4:** Snowflake has no Fact table

## 💡 About this question

Both patterns are built from Fact and Dimension tables. The difference is in the shape of the dimensions:

- **Star:** dimensions are **denormalized** (flat) and attach directly to the Fact; fewer joins, simpler.
- **Snowflake:** dimensions are **normalized** and split into several related tables (e.g., Product → Category → Department); less redundancy but **more joins** and more complexity.

## 🔍 Detailed review of every option

### Option 1 — ✅ Correct

> In Snowflake, Dimension tables are normalized and the number of Joins increases

**Correct.** In Snowflake the Dimension tables are normalized, so there are more tables and the number of joins increases.

### Option 2 — ❌ Incorrect

> Schema is always slower

**Incorrect.** The absolute claim "is always slower" is false (and the option itself is vague: which schema?). Speed depends on data volume, database engine, indexes and more. Snowflake usually has more joins but is not "always" slower.

### Option 3 — ❌ Incorrect

> All items are correct

**Incorrect.** "All items are correct" would hold only if every other option were true, but options 2 and 4 are false.

### Option 4 — ❌ Incorrect

> Snowflake has no Fact table

**Incorrect.** Snowflake has a Fact table just like Star; only the structure of the dimensions is normalized.

## ✅ Correct answer

**Option 1**

> In Snowflake, Dimension tables are normalized and the number of Joins increases

## 🎯 Why it is correct

The key difference: normalized dimensions in Snowflake ⇒ more tables and joins.

## 📌 Key takeaway

Star: simple and flat (fewer joins); Snowflake: normalized and more complex (more joins).
